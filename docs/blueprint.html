Content sourcing — resolved

The brief invited yt-dlp-style extraction and rehosting of copyrighted film and game audio. That is not what got built, and the reason is practical rather than procedural: shipping ripped performances inside a commercial freemium app is what gets an app pulled and a solo developer sued personally.

But strict embed-only was never the right answer either — embeds break, cannot be scored against, and do not work offline. So the pipeline is a real downloader, pointed at content that permits redistribution: tools/ingest reads a video’s license field through the YouTube Data API and pulls only creativeCommon material with attribution retained, alongside bulk LibriVox and Internet Archive ingestion — tens of thousands of public-domain works read by actual humans, which suit Tier 1–2 scoring far better than movie clips would. Embeds survive only for listen-and-analyse lessons, where the point is studying a famous performance rather than scoring against it.

Net: a large local reference library, offline scoring, provenance surfaced in the UI, and no takedown exposure. The compiler enforces the part it can — a creativeCommons or publicDomain reference with no attribution fails the build.

01

The skill tree

Four tiers, 30 core units plus six branching specialization tracks. Tiers are colour-coded on an increasing-energy ramp — the same visual logic as a spectrogram, and the ramp carries through the app’s skill-tree map.

254Lessons on a typical path
390Lessons in the full library
5Mastery levels per lesson
~1,000Sessions to Master
2.7 yrAt one session per day

That last figure is the whole pedagogical bet: 254 unique lessons is not two years of content, but 254 lessons each replayed roughly four times on a widening spacing interval is. Content volume buys variety; the mastery ladder buys duration.

How gating actually works

Completion unlocks nothing. Every gate is a score threshold, and the anti-grind rule is what makes the calendar do the teaching.

MechanismRule
Mastery levelsBronze 60 → Silver 70 → Gold 78 → Diamond 85 → Master 90. A fresh attempt at or above the next threshold promotes the lesson one level.
Anti-grindA given lesson can promote at most once per calendar day. You cannot brute-force a unit in an evening — vocal skill is a motor skill and needs sleep between reps.
Unit gateThe unit’s mastery check unlocks when 80% of its lessons sit at Silver or above. The check is a mixed, previously-unseen battery scored blind against the unit rubric; pass = 75.
DecayEach lesson carries an SM-2-style stability value. When the interval lapses the lesson drops half a level and surfaces in Refresh. It never falls below Bronze once earned — decay nudges, it doesn’t punish.
Tier gateAll units at Gold, plus a tier capstone: an unrehearsed multi-skill performance graded against the tier’s full rubric.

02

System architecture

The organising principle: the client is the product, the backend is a filing cabinet. Every scoring decision that gates progress happens on-device, so the app is fully usable on a plane and no voice recording leaves the phone unless the user asks it to. Third-party media is reached directly by the client and never proxied through our infrastructure.

Routed through our backend Client talks directly — media and events never touch our storage

Framework — confirmed

Flutter, not React Native

Two reasons that are specific to this app rather than general preference. First, macOS is a first-class target here, not an afterthought — this is a studio tool and people will want it on the machine their interface is plugged into. react-native-macos is a Microsoft-maintained fork that lags the main branch; Flutter macOS is in the core SDK.

Second, the two hardest UI surfaces are a 60 fps live pitch/waveform visualiser and an animated skill-tree map. Flutter renders both through its own compositor with CustomPainter and first-party Rive support, with no JS bridge between the audio callback and the paint. That bridge is exactly where RN would hurt.

Backend — confirmed

Supabase, not Firebase

The data is relational and the queries are analytical. Leagues need RANK() OVER (PARTITION BY league_id ORDER BY weekly_xp) with promotion and relegation computed weekly; the curriculum is a DAG of prerequisites; the review scheduler is a range query over due dates. Firestore does all three badly and expensively.

Row-Level Security also maps cleanly onto the two hard policy problems: a moderation queue where a recording is invisible until approved, and minors whose audio is never publicly readable. Those become SQL policies rather than application code you can forget to write. Firebase wins on push maturity and offline-out-of-the-box — but we’re building a custom offline layer anyway.

Offline model

Drift is the source of truth on device; Postgres is a replica the client pushes to. Every mutation lands in a local outbox table with a monotonic sequence number and syncs on reconnect. Attempts, scores, XP, streak state and mastery levels are all computed locally and replayed server-side — a user with no signal for a week loses nothing, and the streak is evaluated against a device-local calendar with a server reconciliation pass to catch timezone gaming.

Only two lesson categories require connectivity: YouTube-embed lessons, and accent drills that use cloud forced alignment. Both are marked in the curriculum data so the skill tree can grey them out cleanly rather than failing at the last second.

03

Where scoring happens

The split follows one rule: anything that gates progress runs on-device. The feedback screen must be fully populated in under 300 ms with numbers, an overlay chart, and a mastery delta — that is the moment the loop either lands or doesn’t. The LLM coach note streams in a beat later as enrichment, and its absence never blocks a score.

Level, noise floor, clippingRMS + peak over the input bufferdeviceNeeded live, during the take, to drive the visualiser and the pre-roll “your room is too loud” gate.
Pitch contourpYIN via a Rust/C FFI plugin, VAD-gateddeviceReal-time overlay against the target curve. Round-tripping this to a server makes the feature impossible.

Calibrating the rubric

The biggest risk in the whole product is that scores feel arbitrary, because a beginner cannot tell a real 68 from a random one — but they can tell when the app disagrees with their own ears twice in a row. Before the rubric weights are frozen, we record a calibration set of roughly 20 takes per lesson type, have them rated by a working VO coach, and tune weights to correlate with those ratings. That set becomes a regression fixture in CI: change a weight, see which calibration takes move.

04

Project structure

A Melos monorepo. Feature-first inside the app, with three enforced import rules: features/ may import core/, domain/ and ui/; core/ may import nothing from features/; and domain/ imports neither — it is pure Dart, so the scoring rubrics and the review scheduler are unit-testable with no Flutter binding. Riverpod for state, go_router for navigation, freezed for models, drift for local persistence.

Two structural notes worth arguing about now rather than in month four. Curriculum is authored as YAML and compiled, not typed into a database — it gets code review, diffs readably, and ships in the bundle so the tree works offline on first launch. And content/references/ stores identifiers only; there is no code path in the repo that can write a media file into it, which is the structural version of the embed-only rule rather than a promise to remember.

05

MVP scope & milestones

One unit, two lesson types, the full sensory layer. The sensory work is in deliberately — the brief’s claim is that haptics and sound are product features, and an MVP without them tests a different product. Scope below is the trimmed version for a solo build at ~10 h/week.

Scope trim — 10h/week

Two cuts that buy back nine weeks

On-device Whisper is deferred. Platform speech recognition handles alignment against a known script well enough, costs nothing, and removes a 150 MB post-install download. Whisper returns when accent drills need it, in Tier 2.

Pitch-match scoring is cut; the visualiser stays. The live contour is the tactile hook and ships in M1. Scoring a user’s contour against a target is a separate problem, and unit 1.3 does not need it.

Together these take the MVP from ~32 weeks to ~23 at 10 h/week. Everything cut is additive later — nothing here is a one-way door.

The unit: 1.3 Articulation & Diction

Chosen over Pitch & Resonance for one reason: its primary signal is the most reliable one we have. Clarity scored against a known script is close to objectively correct, so if the loop feels unsatisfying we’ll know it’s the loop and not the scorer. Five lessons are authored and compiling — plosive precision, sibilance, medial consonants, a tempo ladder, and an over-articulation dial that scores the difference between two takes rather than either one. One embedded-reference lesson proves the listen-and-analyse path.

  • Skill tree showing one unlocked unit and the locked tree beyond it
  • Two lesson types: scored read, listen-and-analyse (embed)

Deferring accounts is the load-bearing scope cut. Anonymous-first means no age gate, no parental consent flow, no COPPA surface and no PII at all in the MVP — because nothing is shared and nothing is uploaded. All of that arrives with community features, where it actually belongs.

Definition of done

A new user opens the app cold, works through five articulation lessons across five days, watches a mastery ring fill, holds a streak, gets one specific and correct-sounding coach note per attempt — and can do all of it in aeroplane mode except the one embed lesson. If that person wants to open the app on day six without a notification, the MVP succeeded.

  1. M0Railsweeks 1–3 · complete

    Pub workspace, app building on all targets with mic entitlements, design tokens and theme, router, the YAML→seed compiler, Drift schema, CI.

    Done so far: workspace and three package scaffolds; macOS and iOS both building; Flutter pinned at 3.47.2 via fvm; colour, type, spacing and motion tokens with full light/dark; the mastery ladder implemented and covered by 13 tests; the curriculum compiler with duplicate-id, dangling-prerequisite and cycle detection; Tier 1 authored with unit 1.3 complete; the skill tree rendering from the compiled seed, covered by 12 more tests.

    Also done: Drift schema with a sync outbox and a tested delete-my-data path; bundled variable fonts; mic entitlements and usage strings on both Apple targets; a CI workflow with stale-seed and stale-codegen guards; and the macOS WebView spike, which passed — see risks.

    Left: the Android SDK wizard and a JDK 21 downgrade, both local-machine setup.

  2. M1Audio spineweeks 4–8 · complete

    The resonance_dsp FFI plugin (YIN pitch, RMS/dBFS, voicing, plosive onset, waveform envelope), PCM capture with frame re-chunking, the live visualiser, and the room-noise pre-roll gate.

    Measured: YIN tracks a tone to better than 0.05% across 80–440 Hz and finds the fundamental of a harmonic-rich sawtooth without octave errors. A 2048-sample window costs 1.17 ms — 7% of a 60 fps frame budget, which settled the window size and confirmed the FFI split was worth it.

    Two bugs caught before they shipped: a 1200 Hz tone reported 400 Hz, because restricting the YIN search to the vocal range makes it land on a genuine multiple of the true period; the search now runs to 2 kHz and range-checks afterwards. And the plugin template’s podspec pointed at a Swift Package layout that does not exist, so the DSP would not have compiled into the app at all.

  3. M2Score & feedbackweeks 9–13

    Platform STT, alignment to the target script, clarity/pace/plosive rubrics tuned against the calibration set, the feedback screen, and the coach-note edge function. Plus tools/ingest for licence-checked reference audio.

    Done: Needleman–Wunsch word alignment with normalisation for contractions, numerals and punctuation; the scoring rubric with its weights and guards; the speech-recognition interface with platform and fake implementations; the feedback screen; the coach-note edge function on Claude Opus 5; and the lesson controller that sequences the whole attempt.

    The ordering is the product: the score is computed entirely on-device and rendered immediately, and only then is the note requested. Someone on a train sees their full breakdown at the same speed as someone on wifi — the only difference is whether a note appears underneath a moment later. Every failure path in the note returns null rather than throwing, and the endpoint answers 200 even on error, because a missing note is not worth retry logic around something already on screen.

    Left: tools/ingest, the coach-rated calibration set, persisting attempts through to the database, and an integration test covering the full record-to-feedback path on a real device.

  4. M3Progressionweeks 14–16 · complete

    Progress now persists. One transaction commits the attempt, mastery, XP, streak and energy together — a promotion whose attempt did not land is an orphan the user cannot explain, and the outbox’s ordering guarantee only holds if they commit as a unit. A test forces a mid-transaction failure and asserts nothing survives it. The outbox is written but not yet drained: recording from the start means the sync consumer arrives to real history rather than a gap where the first weeks of use should be.

    Gating: Silver across 80% of a unit’s lessons. Bronze means passed once, which can be a single lucky take; Silver requires passing again on a later day, which is the first evidence of retention. 80% rather than 100% so one stubborn lesson cannot wall off the curriculum. Unwritten units cannot gate anything — unauthored content blocking progress is indistinguishable from a bug.

    Vocal Energy never blocks. Duolingo’s hearts exist to sell refills; a voice app charging for rest would be a monetisation hook wearing a health costume, and a user who works that out stops believing the vocal-health advice too. Running out offers a real ninety-second exercise — guided box breathing plus straw-phonation humming, a technique that works in a booth without the app — always skippable, restoring two bars rather than five so resting cannot be farmed. A second consecutive low score on one lesson costs double, because repeating a lesson that is not improving is usually fatigue.

  5. M4Sensory layerweeks 17–19

    Haptic registry across Core Haptics, Android VibrationEffect and a macOS no-op; six-sound UI palette; celebration moments; a full reduced-motion path. Ships with placeholder art and sound.

    Proves: premium feel. With placeholders this validates the timing of the feedback, which is the half that is expensive to get wrong; the assets can be swapped later without touching the code.

  6. M5Embed & syncweeks 20–21

    The listen-and-analyse lesson on the embedded player with in/out points, optional Supabase account, outbox sync on reconnect, delete-my-data.

    Proves: the reference path and offline-first sync, the two things that would be expensive to retrofit.

  7. M6Hardenweeks 22–23

    Performance pass, crash reporting, analytics events, accessibility audit including VoiceOver on the lesson runner, TestFlight and internal track.

    Proves: it survives contact with real users on real devices.

Twenty-three calendar weeks at ~10 hours a week. M1 and M2 are the least compressible — they are research as much as construction, and no amount of scheduling makes a pitch tracker behave in a noisy room. If the runway matters more than the scope, the next thing to cut is the embed lesson in M5, which would save two more weeks.

06

Risks worth pricing in now

RiskWhy it bitesMitigation
macOS WebView youtube_player_iframe depends on the webview platform interface, and macOS support there is materially weaker than on mobile. Discovering this in week 13 would be expensive. Resolved. Spiked in M0 as planned, and the ecosystem moved: webview_flutter 4.14 now carries an endorsed macOS implementation via webview_flutter_wkwebview 3.26. macOS builds with the embed player and registers WebViewFlutterPlugin; all three targets share one widget and no fallback is needed. One trap found: without the com.apple.security.network.client entitlement the WebView loads a blank page and reports no error. Entitlement added.
STT size and latency Whisper small is ~480 MB — unacceptable in a first download, and slow on mid-range Android. Resolved for MVP: platform recognisers only, no model download at all. Whisper returns when accent drills need per-phoneme timing, and by then it is a paid-tier feature that can justify the download.
Dart ecosystem version pinning Hit immediately: drift_dev, riverpod_generator and custom_lint could not co-resolve on the machine’s Flutter 3.44, because Riverpod 2 codegen depends on an analyzer needing the macros package Dart has since removed. Flutter pinned per-project at 3.47.2 via fvm, so the shared SDK and the other repos on this machine are untouched. Riverpod moved to 3.x. custom_lint/riverpod_lint dropped — they still pin an older analyzer than freezed 4 allows. Revisit when they catch up; nothing depends on them.
Apple privacy usage descriptions A missing NS*UsageDescription is not a warning or a catchable exception — macOS and iOS terminate the process with SIGABRT the instant the API is touched. NSSpeechRecognitionUsageDescription was missing, so the app died the moment the user pressed Record, with no Dart error and nothing in the console. It was only diagnosable from the crash report’s TCC termination namespace. Key added to both Apple targets, and the speech probe moved into the room check so a prompt lands during a two-second test rather than after a performance. Adding the key was not sufficient: macOS resolves a bundle id through LaunchServices, which indexes built bundles wherever they sit on disk. A leftover build/ios/ bundle from M0 — built before any usage description existed — still claimed app.resonance, so TCC read its plist and killed the app however correct the macOS one was. Diagnosing it took reading the faulting thread’s stack and dumping the LaunchServices database; nothing in the crash report names the shadowing bundle. tools/verify_plists now checks source plists, macOS entitlements, and every built bundle claiming the identifier — each check verified by deliberately breaking it.
The flow is not covered end to end Found in real use, not by the suite: every screen worked in isolation and nothing asserted they connected, so stopping a recording left the user stranded. Two bugs in a row arrived this way. Closed. An integration_test suite now drives the real app binary on macOS and runs in CI. Writing it immediately found a third defect the unit tests could not: the GoRouter was a top-level final, so its navigation state leaked between tests — and across hot restarts. It is now built per app instance. Tests needing the microphone live in a separate file, because the first permission access raises a modal dialog that blocks the run and takes every later test down with it.
Microphone contention The recogniser and the recorder both want the microphone. On Apple platforms speech_to_text drives SFSpeechRecognizer off its own audio engine while record opens its own capture, and whether two clients can tap one input device is platform- and version-dependent. It cannot be settled without a live mic. Speech recognition sits behind an interface with a fake implementation, so the whole scoring and feedback pipeline is built and tested without it. If live capture contends, the fix is one new implementation of that interface — transcribing the finished file instead of listening live — and nothing downstream changes. Needs a real-device test before M2 closes.
Swift Package Manager migration Flutter warns that resonance_dsp does not support SPM and that this will become an error. It is our own plugin, so nobody else will fix it. CocoaPods still works and the DSP framework builds and exports its symbols. Worth converting during a quiet moment rather than under a deadline — the change is a Package.swift and a source move, not a rewrite.
Android build environment The dev machine has no JDK and no Android SDK, so a third of the target platforms is currently unverifiable. Android Studio and Temurin are now installed, but the SDK components still need Studio’s first-launch wizard. Pitch tracking on real rooms pYIN degrades badly with room noise and phone-mic AGC, and a wrong contour reads as the app being broken. Hard-gate scoring behind the noise-floor check, VAD-gate the tracker, and show confidence in the overlay rather than drawing a confident wrong line.
Scores feel arbitrary Two disagreements with the user’s own ears and trust is gone for good. The coach-rated calibration set from §3, wired into CI as a regression fixture.
Original art and sound M4 assumes a mascot and a six-sound palette exist. Neither is an engineering task, and the brief rules out anything derivative. Commission both during M1–M3 so they land before M4 starts. Needs a budget decision now, not in week eleven.
The name “Resonance” is a common product word — there are meditation, audio and wellness apps using it, which makes both the App Store listing and the trademark position weak. Worth a search before launch. If you want alternatives from the same world: Timbre, Booth, Slate. Cheap to change now, expensive after TestFlight.

Where M0 stands

  • Building: macOS and iOS compile, run, and register the WebView plugin. Android is scaffolded but still needs Studio’s SDK wizard and a JDK 21 downgrade.
  • Tested: 40 passing, analyzer clean, formatter clean. 13 on the mastery ladder (thresholds, the once-per-day rule, decay floors, a five-day climb, and a grind attempt that correctly gets nowhere); 15 on persistence (mastery round-trip, XP accumulation, outbox ordering, and a delete-my-data check that asserts the outbox is emptied too); 12 on the curriculum pipeline and skill tree.

  • Rendering: the skill tree draws all eight Tier 1 units from the compiled seed with segmented mastery rings, locked states, and unauthored units showing their planned size. Archivo, Newsreader and JetBrains Mono are bundled as variable fonts.
  • Persistence: Drift schema covering mastery, attempts with separable score components, streak, daily XP and the sync outbox. Delete-my-data is implemented and tested.
  • CI: analyze, format, test, curriculum compile, a stale-seed guard, a stale-codegen guard, the native DSP harness, and builds for all three platforms.
  • Audio (M1): the DSP plugin with 27 native algorithm checks and 21 FFI binding tests; PCM re-chunking that provably loses no sample across ragged callbacks; the semitone-axis visualiser that gaps across breaths rather than drawing a line to zero; and a room check that runs before the take.
  • Scoring (M2): word alignment that reports a dropped word as one omission rather than cascading into a false near-total failure; a rubric whose most important test is simply that a better read always outranks a worse one; and a feedback screen that marks the script where words were lost, because “Clarity 78” teaches nothing and a struck-through “batch” teaches immediately.
  • Streak rules: the freeze is spent automatically, because at the moment the decision would need making the user is by definition not in the app. One missed day is covered; two are not — a freeze is for a bad night, not a lapsed habit, and papering over more would make the number mean nothing.
  • Progression (M3): persistence in one transaction with a rollback test; unit gating that requires evidence of retention rather than a single good take; and an energy meter with no way to express a refusal — the type has no method that can block an attempt.
  • Privacy boundary, enforced in the type system: the coach-note client’s signature accepts a transcript and numbers and has no parameter through which audio could be passed. The edge function additionally rejects any request body carrying an audio field, so widening the boundary later takes a deliberate change in two places.
